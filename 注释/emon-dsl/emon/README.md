# ===================================================================
# emon/ 目录 —— Python 编译器核心代码
# ===================================================================
#
# 【目录用途】
# 这是 Emon DSL 编译器的"大脑"所在。整个目录包含用 Python 编写的
# 完整编译流程：从读入 .emon 源文件，到生成最终的 eBPF C 代码。
#
# 【各文件职责（按编译流水线顺序）】
#
#   __init__.py     → Python 包标识文件（内容为空，使 emon/ 成为可导入的包）
#
#   tokens.py       → 词法单元(Token)定义
#                     定义了所有"单词"类型：关键字、标识符、数字、字符串、
#                     时间字面量(如 100us)、大小字面量(如 256KB)等
#
#   error.py        → 错误类型定义
#                     定义了词法分析阶段的错误类：非法字符、未闭合字符串、
#                     未闭合注释、无效数字等
#
#   lexer.py        → 词法分析器（编译器第一阶段）
#                     将原始字符串源代码拆分为一个一个的 Token（单词）
#                     例如 "observe syscall" → [KEYWORD("observe"), KEYWORD("syscall")]
#
#   ast_nodes.py    → 抽象语法树(AST)节点定义
#                     用 Python 数据类定义了程序的所有语法结构：
#                     工具声明、观察规则、表达式、动作语句等
#
#   parser.py       → 语法分析器（编译器第二阶段）
#                     基于 Lark 解析框架，将 Token 序列组织成树状 AST 结构
#                     例如 Token 序列 → Program(ToolDecl(...), ObserveRule(...))
#
#   semantic.py     → 语义分析器（编译器第三阶段）
#                     检查 AST 的逻辑正确性：变量是否定义、类型是否匹配、
#                     上下文变量是否在正确的 hook 类型下可用
#
#   ir.py           → 中间表示(IR)构建器（编译器第四阶段）
#                     将 AST 转换为编译器内部使用的数据结构（IR），
#                     为后续代码生成做准备。同时也包含编译主入口函数。
#
#   bpfc_gen.py     → eBPF C 代码生成器（编译器第五阶段-A）
#                     从 IR 生成可在内核中运行的 eBPF C 程序(.bpf.c)
#
#   loader_gen.py   → 加载器代码生成器（编译器第五阶段-B）
#                     从 IR 生成用户态 libbpf 加载器 C 程序(_loader.c)
#
#   manifest_gen.py → 清单文件生成器（编译器第五阶段-C）
#                     从 IR 生成 YAML 格式的工具描述文件(.yaml)
# ===================================================================
